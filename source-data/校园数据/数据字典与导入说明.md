# 数据字典与Java/MySQL导入说明

所有CSV均为UTF-8带BOM，适合常见电子表格软件；JSON为UTF-8。每张业务表在`cleaned/`下有同名CSV、JSON。开发优先读JSON以保留`null`、布尔值、数组和嵌套标签。CSV中的数组/对象使用JSON字符串，空字段对应JSON中的`null`；可能触发电子表格公式的文本前加单引号，仅影响CSV展示。

完整字段、观察到的类型与缺失数量见[字段清单](字段清单.json)。以下定义说明不能从类型直接理解的业务含义。

## 通用约定

| 字段 | 含义与约束 |
|---|---|
| `campus_id` | 当前统一为`SWJTU_XIPU`；周边记录表示为此校区服务的研究范围，不等于位置一定在校内 |
| `place_id` / `gate_id` / `node_id` / `edge_id` | 稳定文本ID，保留来源前缀，禁止仅按名称当主键 |
| `name` | 规范化的来源名称；未命名时为`null`，不能将ID当正式地名 |
| `source_name` | 未作字符规范化的来源名称 |
| `source_id` | 外键指向根目录`sources.json`中的S01–S11 |
| `source_record_ids` | 官方保留下来的原始编号列表；去重时可有多个编号 |
| `source_entity` | `organization`与`public_point`属于不同来源实体空间，相同数字不代表相同记录 |
| `source_file` | 采集阶段的历史快照文件名，仅作来源标识；中间快照已删除，不是当前可打开的本地路径。请通过`source_id`查阅`sources.json`中的公开链接 |
| `source_published_at` | 来源发布日；未知为null。不同于采集日 |
| `source_updated_at` | OSM该要素编辑时间，不证明现场核实或当前可通行 |
| `collected_on` | 本次采集日期2026-11-03，不是所有资料的内容年份 |
| `availability` / `current_passability` | `unverified`表示未确认现实营业、开放或通行状态 |
| `routing_ready` | 本包均为false，明确表示还没有通过实际通行验收 |

## 位置与坐标

| 字段/文件 | 定义 |
|---|---|
| `source_longitude` / `source_latitude` | 官方矢量地图原值；`coordinate_system=UNDECLARED`，不直接混入OSM路网 |
| `longitude` / `latitude` | OSM来源或其几何派生点，为WGS84，经度在前、纬度在后 |
| `position_role=mapped_point` | OSM标注点。也不等于已验收的楼宇入口 |
| `position_role=footprint_centroid_not_entrance` | 闭合轮廓的平面面积质心，仅用于代表/展示建筑；可能不适合作为导航起点 |
| `position_role=vertex_mean_not_entrance` | 非闭合几何节点均值，是派生展示点，不是实测位置 |
| `rasterLngLatString` | 官方平台的图示位置字段，未纳入精简后的数据文件。不能作为真实经纬度导入 |
| GeoJSON | 遵循经度、纬度顺序。均来自OSM的WGS84；没有为未知坐标系的官方点生成GeoJSON |
| `scope=inside_mapped_campus` | 代表点位于OSM校园面内；不是校方确认的产权或管理范围 |
| `scope=outside_mapped_campus` | 位于校园面外的周边候选数据，不能展示成“校内设施” |

向地图SDK传坐标前，按该SDK要求显式转换。WGS84、GCJ-02、BD-09和校园原图图示位置不能混用；未知坐标系应先核实。

## 地点、别名与跨来源关联

- `official_places`：27条建筑/宿舍组团和172条去重后的生活设施。`category_raw`保留平台类别；`category`仅是项目归类。官方把图书馆归入综合办公大楼，因此项目类型为`office_or_library`，不代表它是行政办公室。
- `official_transit_references`：官方表的16条子集；`category_raw`可能需要运营方核对。它不是完整站点库。
- `place_aliases`：一条地点可有多个词；`alias_kind=project_search_alias`是项目人工搜索配置，来源ID为空；`campus_context_required=true`表示应限定犀浦校区语境。别名不全局唯一，搜索结果需要消歧。
- `official_supplementary_names`：23条官方地图/公告名称证据。`label_id`是人工事实条目ID；`evidence_kind`区分`visual_map_label`和`notice_name`。位置为空，不自动与OSM同名对象合并。
- `osm_campus_places`：含有名称或出行设施标签的校园对象，并非274个已去重的独立目的地；同一建筑可能同时有轮廓和功能点。
- `osm_buildings`：97个建筑轮廓的属性及派生代表点，轮廓见GeoJSON；保留未命名建筑。
- `osm_type` / `osm_id` / `osm_version`：原始OSM对象类型、编号、版本；`tags`完整保留所选对象的地图标签，不包含用户账号元数据。
- `place_crosswalk_candidates`：23条基于规范化名称的跨来源候选关联。`match_status=candidate_requires_review`且`coordinate_merge_allowed=false`，不将“同楼的学院机构”自动等同于“整栋建筑”。
- `mvp_seed_candidates`：校园OSM表中的10条子集；`entry_node_id=null`等待确认入口。这不是另造的模拟地点。
- `nearby_transit_osm`：24条周边交通对象；站台、轨道停车点、车站点、出口各自保留，部分名称为空、出口编号在`tags.ref`。未经关系核对，不给未命名出口强加所属站名。
- `nearby_campus_named_osm`：4条校外同名相关对象，包括医院、驾校、小学；并非已确认均属于本项目的校内设施。

## 校门与候选路网

| 字段 | 定义 |
|---|---|
| `gate_id` | OSM栏杆/门节点ID，不能假定每个门都是学校大门 |
| `role=campus_gate_candidate` | 来源名符合具名校门候选且距校园边界不超过100米，属于待审规则，不是校方核验 |
| `boundary_distance_m` | 代表点至OSM校园边界的几何近似距离；不是实际步行距离 |
| `on_graph_node` | 此门节点是否直接属于候选道路图。true不代表已确认能通行 |
| `opening_hours` | OSM原始标签；缺失为空，不默认24小时 |
| `from_node_id` / `to_node_id` | 指向`graph_nodes_candidates.node_id`；拆分自OSM道路相邻节点，无人工补边 |
| `osm_way_id` / `segment_index` | 原始道路对象与其中相邻节点段序号；一个way可有多条边 |
| `length_m` | WGS84球面Haversine段长，单位米。是几何估算，不是现场测距、通行耗时或文字通知距离 |
| `highway` / `access` / `foot` | 原始道路类型、访问权限和步行标签；缺失为空 |
| `walk_permission` | 清洗规则生成的权限状态：prohibited、conditional、explicit_foot_tag、unspecified |
| `walk_permission=prohibited` | 来源步行禁止、入口禁止或不适合作步行的道路类型；不能作为默认步行边 |
| `walk_permission=conditional` | 有private/permit/customers/destination等限制；仍需逐项核对，包括foot例外 |
| `walk_permission=explicit_foot_tag` | 道路有明确foot=yes/designated，仍不代表当前现场开放或无障碍 |
| `walk_permission=unspecified` | 没有明确步行许可信息，禁止解释为“已经确认开放” |
| `foot_direction` | `oneway:foot`原值，未标注时unspecified；不擅自将机动车单向当步行单向 |
| `vehicle_oneway` | 机动车相关oneway原值，供后续审阅 |
| `layer` / `bridge` / `tunnel` / `surface` | 来源层级、桥隧、路面标签；不按几何交叉自动连接不同路段 |
| `crosses_campus_boundary` | 两端不都在校园面内，当前18段；整段保留用于边界审阅，没有伪造边界交点 |
| `component_id` / `degree` | 忽略访问限制、按OSM共享节点计算的无向几何连通分量及邻接度；不是许可通行网络 |
| `osm_road_areas.geojson` | 7个面积式道路/广场对象，单独保存，不把区域边界冒充道路中心线加入图 |

道路图以OSM共享节点连接，未生成楼宇入口、最近道路投影点、跨河捷径、推断校门连接或步行时长。不要将候选边表导入后直接开放用户导航。

## 时刻、通知与接驳

- `historical_shuttle_departures_2022`：一行一个历史发车时刻；`day_type=weekday/weekend`是原公告分类，不能自行当作节假日日历。`effective_until=null`表示未知截止日，不表示永远有效。
- `shuttle_changes_2025`：一行一条增量变更。`vehicle_count_change`只改变车辆台数，不新增发车时刻；`trial=true`为试运行。所有`enabled_for_live_routing=false`。
- `departure_time`：本地时刻HH:mm。不是Unix时间戳，不自动绑定今天或生成到达时间。
- `connector_evidence`：一行一条官方文字证据。`distance_m`是来源约数；同一D2至西门保留300米和500米冲突。`geometry=null`表示没有本包可用的地理路线，不得画成已核实路径。
- `construction_notices`：`planned_start/planned_end`是公告计划日；`current_verified=false`。`automatic_road_closure=false`，原图没有地理配准，不生成精确围挡多边形。

## Java/MySQL使用顺序

1. 优先读取JSON，先导入来源表、地点目录、别名和10条候选点；保留不同来源的文本主键。地点名不能做唯一键。
2. 标识符用`String`/`VARCHAR`；经纬度用可空`Double`或`BigDecimal`；日期与HH:mm分开保存；JSON布尔值保持布尔类型。
3. 保留`coordinate_system`、`position_role`、`source_id`和验收状态。不要在导入时把未知值、缺失值转为0、false或“24小时”。
4. 节点表先于边表导入，按`from_node_id/to_node_id`建立外键。正式可用的步行图应是审核后的独立版本，不能修改原始来源表来掩盖未知状态。
5. 规范化表可以拆分`tags`和来源编号；若先存JSON列，也要保留原文件和数据版本。不同来源同名记录通过人工确认的关联表处理。

本包不包含账号、密码、注册登录表，也不要求先开发账户系统才能导入和使用这些校园业务数据。
